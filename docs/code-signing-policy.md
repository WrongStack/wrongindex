# Code signing policy

Status (2026-11-12): SignPath Foundation preparation is in progress. No Foundation subscription, certificate or production signing approval is claimed. Existing public releases and the retained 0.2.0 engineering candidates are unsigned. Signed preview workflows must fail when provider configuration or a trusted signature is missing; the source of truth for each published file is its release manifest and attestation.

## Scope and roles

Only WrongIndex programs and installer/uninstaller images built from this public repository by GitHub-hosted workflows are eligible for this pipeline. Third-party executables are not submitted under the project's identity. Product and version metadata are checked before submission. The signing workflow accepts only the canonical repository's `main` branch; final publication promotes the same qualified signed artifact rather than rebuilding it.

The five NSIS plugins used by the pinned Tauri bundler retain their upstream bytes. `.signpath/nsis-vendor.json` is generated by `scripts/release/signpath/export-nsis-vendor.ps1` from the official NSIS 3.13 archive and Tauri utility 0.5.3 DLL, verified against GitHub release SHA-256 digests and the bundler's recorded SHA-1 baseline. The compiler hook accepts only their exact names, paths and SHA-256 hashes; unknown or modified DLLs fail. Preserving these files is not a claim that they carry a WrongIndex signature.

Project maintainer, reviewer and proposed signing approver: [@ersinkoc](https://github.com/ersinkoc). The owner confirmed GitHub MFA on 2026-11-12. Production enrollment also requires MFA for the signing account and the provider's release approval policy; provider account setup/enrollment has not been completed or verified.

The [SignPath Foundation terms](https://signpath.org/terms) and [GitHub origin verification documentation](https://docs.signpath.io/trusted-build-systems/github) define the external service requirements. If the application is accepted, the project will add the confirmed provider attribution and its approved signing roles to the download/release page. It must not advertise provided signing before acceptance.

## Data and verification

The standalone native indexing service works with local source files and indexes. Signing submits CI-built program images and GitHub build-origin metadata, not a user's registered project or database. Install/update operations contact GitHub; the legacy desktop's optional daily update check is opt-in. Separately configured WrongStack compatibility backends follow their own provider and data settings.

Private keys remain with the signing provider. The CI submitter credential is a protected action input; it is not passed to compiler hooks, command arguments, the application or the GUI. Responses must match the requested executable content and approved public certificate digest. Archive extraction accepts only expected file names and bounded sizes. The generated uninstaller is signed and its installed bytes are checked too.

Code signing does not replace tests. A signed preview still requires clean-Windows startup/install/uninstall, host integration, final-artifact durability, manual GUI acceptance and the release evidence recorded in [status.md](status.md). `WRONGINDEX_QUALIFIED_SIGNING_RUN_ID` must only designate the exact run accepted by these gates; it is not set by a successful signing request alone.
